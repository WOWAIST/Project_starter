# PRD - DeepRead

1. Product Vision

번역기는 이해를 대신해주지만 실력을 남기지 않는다. DeepRead는 한국 개발자가 영어 기술 문서를 "읽어내는 훈련"을 하도록 만들어, 결국 DeepRead 없이도 원문을 읽는 상태로 이끈다. 도구 의존을 늘리는 것이 아니라 줄이는 것이 이 제품의 존재 이유다.

우리는 문서를 번역해주지 않는다.

우리는 사용자가 원문을 구간 단위로 읽고,
자기 말로 설명하고,
피드백으로 이해를 교정할 수 있도록 AI로 돕는다.

⸻

2. Problem

현재 사용자는 영어 기술 문서를 읽어야 하는 상황에서 다음과 같은 문제를 겪는다.

1. 번역기로 읽으면 당장 이해는 되지만 독해력이 늘지 않는다.
2. 원문으로 읽어도 제대로 이해했는지 확인할 방법이 없다.
3. 기술 용어는 사전식 번역이 오히려 혼란을 준다.
4. 일반 영어 학습 앱은 실무 문서와 동떨어져 동기가 유지되지 않는다.

결과적으로 실력이 늘지 않는 번역 의존 상태에 머문다.

⸻

3. Product Goal

사용자가

"영어 문서가 열리면 반사적으로 번역기부터 켜는 상태"

를 넘어서

"원문을 그대로 읽고, 필요할 때만 도움을 요청하는 상태"

에 도달하게 만든다.

⸻

4. Target User

Primary

* 업무상 영어 공식 문서·릴리즈 노트를 읽어야 하는 주니어~미들 한국 개발자
* 번역기 의존을 벗어나고 싶지만 혼자서는 방법을 못 찾은 개발자

Secondary

* 영어 기술 아티클로 학습하려는 개발 입문자

⸻

6. MVP Scope

포함

* 문서 입력 (URL 또는 텍스트 붙여넣기) → 구간 자동 분리
* 구간별 이해도 질문 생성
* 사용자 설명 입력 → AI 평가·피드백
* 핵심 기술 용어 추출과 문맥 기반 개념 설명
* 학습 기록·독립성 지표 대시보드
* GitHub OAuth 로그인

제외

* 전문 번역 기능 — 제품 철학과 정면 충돌
* 모바일 앱 / 익스텐션 — 반응형 웹으로 충분, 기간 제약
* 소셜·커뮤니티 기능 — 학습 루프 검증이 먼저
* 영어 외 원문 언어 — 타겟 문제에 집중

⸻

8. Core Feature Flow

구간 학습 루프 (Reading Loop)

STEP 1

문서 인제스트

URL의 본문을 추출하고 의미 단위 구간(chunk)으로 나눈다. 광고·내비게이션은 제거한다. 원문을 수정하거나 번역하지 않는다.

⸻

STEP 2

원문 읽기

사용자는 구간 원문을 그대로 읽는다. 이 단계에서 시스템은 개입하지 않는다.

⸻

STEP 3

이해 질문

AI가 구간의 핵심을 겨냥한 질문 1개를 생성한다. 사실 확인이 아니라 "왜/어떻게"를 묻는다. 답을 유도하는 힌트를 먼저 주지 않는다.

⸻

STEP 4

자기 말로 설명

사용자가 한국어 또는 영어로 자유롭게 설명을 입력한다.

예시

* "여기서 hydration은 서버가 그린 HTML에 클라이언트 이벤트를 붙이는 과정이라는 뜻"
* "이 옵션을 켜면 번들에서 안 쓰는 코드가 빠진다는 얘기"
* "잘 모르겠다 — suspense가 왜 필요한지 이해 안 됨"

⸻

STEP 5

AI 평가·피드백

원문 근거를 인용해 무엇을 맞게 이해했고 무엇이 빠졌는지 알려준다.

⸻

STEP 6

판정과 진행

* 이해함 → 다음 구간으로
* 부분 이해 → 보완 포인트 제시 후 재설명 1회
* 다시 읽기 → 원문으로 복귀 (힌트는 요청 시에만)

판정

⸻

9. Reading Independence Levels

Level 1 — 가이드 리딩

모든 구간에서 질문·용어 카드가 기본 제공된다. 신규 사용자 기본값.

⸻

Level 2 — 보조 리딩

용어 카드는 요청 시에만. 질문 빈도가 구간 2개당 1회로 줄어든다. 힌트 요청률이 기준 이하로 내려가면 자동 제안.

⸻

Level 3 — 독립 리딩

시스템 개입 없이 완독 후 전체 요약 설명 1회만 평가받는다. 이 레벨의 유지가 제품의 성공 상태다.

⸻

10. AI / System Rules

절대 문장 단위 번역을 제공하지 않는다 — 용어의 개념 설명까지만.

절대 사용자의 설명을 대신 작성하지 않는다 — 빈 답변에 모범 답안을 주지 않는다.

피드백은 항상 원문 근거를 인용한다.

힌트는 단계적으로 준다 (위치 힌트 → 개념 힌트 → 설명). 한 번에 전부 주지 않는다.

평가 어조는 교정 중심이되 지속 동기를 꺾지 않는다.

AI 응답은 스키마 검증을 통과한 경우에만 사용자에게 노출한다.

⸻
